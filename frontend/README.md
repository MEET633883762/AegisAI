# AegisAI static research demo

The frontend is dependency-free static HTML, CSS, and JavaScript. It has no backend and cannot execute simulator actions.

## Pages

- `index.html` is the public-facing project landing page.
- `dashboard.html` contains the precomputed interactive research episode and the existing local website header assessment comparison.

To preview from the repository root:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory frontend
```

Open `http://127.0.0.1:8765/` and choose **Explore the demo**. The dashboard is at `http://127.0.0.1:8765/dashboard.html`. This preview uses port 8765, which is also used by the separate local website demo server; stop one server before starting the other.

## Interactive sample provenance

`data/public_demo_episode.json` is a reviewed, precomputed artifact from one deterministic `credential_reuse_known_vuln` episode with seed `1`. That pair is a training sample in the repository's research split. It was generated by the existing Python simulator, `Controller`, `ScriptedRedAgent`, and `ScriptedBlueAgent` through `scripts/build_public_demo_artifact.py`.

The artifact contains Controller sequence/step/role/action/authorization/outcome data, typed-action validation results observed at export time, and evidence extracted from the corresponding role-specific pre-action XAI observation. The export omits audit `state_changes` and audit `event_ids`; evidence is published only with its originating role scope. Metrics include definitions and observed numerators/denominators. Decision latency is omitted because it was not collected for this export. This one scripted episode is not representative research evidence of real-world security effectiveness.

To regenerate the static sample locally, run `python scripts/build_public_demo_artifact.py`. This runs one deterministic simulator episode and writes only `frontend/data/public_demo_episode.json`. The public page fetches that file and never runs the Python script or simulator. Review the artifact before publishing changes.

The browser accepts only schema version `1.0`, validates required fields, role scopes, metric denominators, and a 1 MB maximum, and renders artifact strings as text. The **Download sample report** link downloads the same static JSON artifact.

## Local website header assessment

The dashboard preserves local file import and baseline-versus-hardened comparison. Run `python scripts/check_demo_site.py` while the loopback-only demo server is running, then choose the generated reports in the dashboard. The checker remains fixed to `127.0.0.1`; its result covers HTTP status and four configured response headers only. It is not a general website scanner or security assessment.

The report import happens in the browser using locally selected files. The importer validates the expected local assessment schema, fixed loopback target, profile, required fields, and 1 MB maximum. Report strings are escaped before rendering.

The dashboard also loads the two sanitized, reviewed sample reports from `data/public_demo_assessment_baseline.json` and `data/public_demo_assessment_hardened.json`. This button fetches fixed same-origin sample paths; selected local files are still only read in the browser. Original evidence artifacts in the repository `results/` directory are not included in the static deployment output.

## Privacy and static release

See `privacy.html` for the current visitor data disclosure. The site contains no accounts, database, analytics, or report upload. The hosting provider may process connection/request metadata under its own policies.

Build the strict, dependency-free publication allowlist from the repository root with:

```powershell
python scripts/build_static_site.py
```

This writes only the approved website files to `dist/aegisai-static/` and refuses to write into a non-empty output directory. Publish that generated directory only; do not publish the repository root or `frontend/` directly. See `docs/PHASE4_RELEASE_HARDENING_AND_DEPLOYMENT.md` for the release procedure and checks.

## Tests

Run the frontend tests with:

```powershell
node --test tests/frontend/public_shell.test.js tests/frontend/research_demo.test.js
```

Run the repository Python suite from the project root with `python -m pytest -q`.
